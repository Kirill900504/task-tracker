## 2. Как развернуть на новом устройстве

1. Поставить Node.js 24 (здесь `v24.19.0`) и Git.
2. Получить код — любой из двух путей:
   ```bash
   git clone https://github.com/Kirill900504/task-tracker.git
   ```
   или из архива, без сети:
   ```bash
   git clone repo/task-tracker.bundle task-tracker
   ```
   (после клона из бандла: `git remote set-url origin https://github.com/Kirill900504/task-tracker.git`)
3. Положить `secrets/.env.local` в корень проекта, `secrets/vercel-project.json`
   как `.vercel/project.json`.
4. `npm install`, затем `npm test && npm run lint && npm run build`.
5. Vercel CLI: либо `npx vercel login` (вход Кирилла), либо скопировать
   `secrets/vercel-cli-auth.json` в
   `%APPDATA%\com.vercel.cli\Data\auth.json` (Windows) /
   `~/.local/share/com.vercel.cli/auth.json` (Linux) /
   `~/Library/Application Support/com.vercel.cli/auth.json` (macOS).
6. Git push: при первом `git push` Windows/Git попросит войти в GitHub
   (аккаунт `Kirill900504`) — токен хранится в диспетчере учётных данных
   Windows и из него не выгружается, поэтому переносится только входом.
7. Для Claude: содержимое `claude/` разложить так, как написано в
   `claude/КУДА-КЛАСТЬ.md`.

Рабочая копия на старой машине лежит в `OneDrive\Desktop\task-tracker`;
сессии Claude работали в `.claude/worktrees/*` внутри неё.

| **Supabase** | Postgres + Auth + Realtime + Storage, регион `eu-central-1` | URL, anon- и service-role-ключи, `DATABASE_URL` — в `secrets/.env.local`. Вход в панель supabase.com — аккаунт Кирилла |
| **GigaChat** | ключ API (пакеты Max/Pro/Lite) | `GIGACHAT_AUTH_KEY` в `.env.local` |
| **Telegram-бот** | токен, имя, секрет вебхука | `TELEGRAM_*` в `.env.local`; управление — @BotFather в Telegram Кирилла |
| **MAX-бот** | «РОКАС Трекер» `@id6168118162_4_bot`, ООО «РЕГИОН КАСС» | токен и секрет вебхука лежат в **базе**, таблица `bot_settings` (подключается страницей `/max`); кабинет — business.max.ru, вход Кирилла |
| **Крон** | `CRON_SECRET` | `.env.local`; см. «Неизвестное» ниже |

Переменные окружения (полный список — HANDOFF.md, раздел 9) продублированы
в Vercel → Settings → Environment Variables; `.env.local` — их локальная
копия. `VERCEL_OIDC_TOKEN` в нём короткоживущий и обновляется сам
командой `npx vercel env pull`.

**Обращение с секретами.** Архив с `secrets/` даёт полный доступ к базе
(service-role ключ обходит все правила доступа) и к ботам. Передавать
только лично или по защищённому каналу, не пересылать в мессенджерах и
почте целиком. Если архив утёк — перевыпустить: service-role ключ
(Supabase → Settings → API), токен Telegram (@BotFather → /revoke), ключ
GigaChat, `CRON_SECRET` и `TELEGRAM_WEBHOOK_SECRET` (после смены — заново
поставить вебхук).

**Неизвестное, что надо выяснить у Кирилла:** какой внешний сервис раз в
несколько минут вызывает `/api/cron/reminders` (в репозитории не записано;
бесплатный крон Vercel ходит раз в сутки, поэтому нужен сторонний пингер).
Без него молчат напоминания, сводки и эскалация просрочки. Резервная
копия (`/api/cron/backup`) — крон самого Vercel, `vercel.json`.

## 6. Как работать в новом чате

Новая сессия Claude подхватывает проект сама, если `CLAUDE.md` в корне
репозитория и глобальный `~/.claude/CLAUDE.md` на месте. Главное, что
должно пережить переезд:

- **Всё, что видит Кирилл, — по-русски** (ответы, рассуждения, отчёты);
  код, комментарии и коммиты — по-английски.
- Он не технарь: делать самому, а если нельзя — прямая ссылка и одно
  действие.
- Готовое сразу в `main` и push (= деплой), но только после зелёных
  `npm test`, `npm run lint`, `npm run build` (и e2e, где изменение видно).
  Отчитываться после того, как деплой Vercel в состоянии Ready и проверен
  на боевом. Последняя команда перед «готово» — `node scripts/unmerged.mjs`.
- `docs/HANDOFF.md` обновлять в том же коммите, если меняется концепция,
  правило или крупная функция.
- Несколько сессий могут работать в одной копии: `node scripts/claim.mjs`,
  коммитить только свои пути (`git commit -- путь…`).

**Запланированные задачи Claude** (в архиве `claude/scheduled-tasks/`):
`finish-unfinished-hourly` — раз в час доделывает работу по запискам из
`.unfinished/` (актуальная); `finish-unfinished` — её старая версия с
каталогом вне рабочей копии (выключена, не восстанавливать);
`max-bot-activate` — разовая задача 14.09 на подключение MAX, выполнена,
не восстанавливать. Новую запланированную задачу первый раз запускают
вручную при человеке — иначе она встанет на запросе разрешения.
Собственных скиллов (`~/.claude/skills`) у проекта нет; использовались
только встроенные.
